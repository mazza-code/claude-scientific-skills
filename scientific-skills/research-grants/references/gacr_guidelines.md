# Czech Science Foundation (GACR) Proposal Guidelines

> Important: This guidance must always be paired with the specific call tender document. If there is any conflict, follow the call's official Czech text.

## Overview

The Czech Science Foundation (Grantova agentura Ceske republiky, GACR) funds basic research through structured public tenders and calls. For writing support, treat GACR as:

- Scientifically similar to NSF in emphasis on originality, significance, and feasibility.
- Procedurally strict on formal compliance (format, language, forms, budget syntax, and submission channel).
- High-risk for disqualification if formal conditions are not met.

This guide defines the generic GACR track. Call-specific constraints (limits, dates, and forms) are handled by call profiles such as `GACR_STD_2027`.

## Track And Profile Model

When using this skill for Czech grants, use two levels:

1. Agency track: `GACR`
2. Call profile: specific tender, for example `GACR_STD_2027`

Always state both at the start of work:

- `Agency track: GACR`
- `Call profile: GACR_STD_2027` (or another active profile)

If no profile is available, create a provisional profile from the official call documents before drafting narrative text.

## Proposal Architecture (Generic GACR Pattern)

GACR proposals are structured into fixed parts (A, B, C, D, E), with call-specific limits and form requirements:

- Part A: identification + abstract + scientific aim
- Part B: financial structure + detailed justification
- Part C: scientific justification and expected outputs
- Part D: CV and bibliography/track record
- Part E: other projects and overlap disclosures

For most calls, these parts are entered via the official submission system and some parts (for example C1 and D1) are uploaded as external PDF files.

## Evaluation Logic

GACR evaluation is typically split into:

1. Admission/formal screening
2. Verification of correctness/completeness
3. Scientific quality assessment (panel-based, with external review stages depending on call)
4. Proposed costs assessment

Scientific criteria usually include:

- Clarity and significance of aims
- Quality and adequacy of methods
- Team competence and role/workload logic
- Expected output quality
- International collaboration value (if applicable)
- Feasibility relative to requested resources

Budget criteria usually include:

- Legitimacy of cost items
- Workload-cost consistency
- Compliance with eligible-cost definitions and caps
- Proportion of requested GACR funding

## Disqualification Risk Mindset

Unlike many agency systems where formatting errors are fixable later, GACR calls can disqualify proposals for formal errors. The writing process must include a strict admissibility gate.

Treat the following as hard-fail categories:

- Wrong language (where English-only is required)
- Missing mandatory parts
- Exceeded page/size/format limits for uploaded files
- Non-permitted attachments
- Incorrect financial syntax (for example, wrong currency format)
- Contradictory or false information
- Missing required declarations/disclosures

## Writing Strategy For GACR

Use an NSF-like scientific narrative, but with tighter formal controls:

- Frame a clear knowledge gap and a testable hypothesis.
- Explicitly connect methods, risks, timeline, and outputs.
- Keep role definitions and FTE logic internally consistent with budget tables.
- Make expected outputs specific and credible for the project horizon.
- Integrate a data handling/data management description where required.

## Mandatory Output Bundle For This Skill (GACR Mode)

When drafting or reviewing a GACR proposal, always produce:

1. Scientific draft content for requested parts.
2. A formal-compliance checklist mapped to the active call profile.
3. A "disqualification risk" list with concrete fixes.
4. A consistency table aligning:
   - aims
   - methods
   - milestones
   - outputs
   - budget/FTE

Do not finalize proposal text without passing the formal-compliance checklist.

## Visual Requirement

Include at least 1 visual in the proposal package (preferably 2):

- project logic flow
- timeline/Gantt
- work-package dependency map

Use scientific-schematics for generation and iterate until the figure supports reviewer readability.
